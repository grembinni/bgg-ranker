# Requirements Archive: v0.9

**Milestone:** v0.9 Core Loop
**Archived:** 2026-05-25
**Original definition:** 2026-05-22

## v1 Requirements — Final Status

### Authentication

- [x] **AUTH-01**: User can enter BGG username and password to start a session (credentials held in memory only — never written to localStorage or disk) — **Validated** (Phase 3, Plan 03-03)
- [x] **AUTH-02**: App warns the user before tab close if any comparisons have been made since the last BGG sync (unsynced-changes guard) — **Validated** (Phase 3.1 — uses dirtyGameIds.length > 0)
- [x] **AUTH-03**: When a BGG write call returns 401 (session expired mid-session), the app prompts the user to re-enter credentials before retrying sync — **Validated** (Phase 3, Plan 03-04 SyncingView re-auth)

### Collection

- [x] **COLL-01**: App fetches the user's owned board games from BGG XML API2 (excludes expansions by default) — **Validated** (Phase 2, Plan 02-02)
- ~~**COLL-02**: User can toggle to include expansions in the comparison pool~~ — **Deferred to v2** (2026-05-23 Phase 2 discuss-phase: boardgames only in v1)
- [x] **COLL-03**: App also fetches unowned games the user has previously rated on BGG and includes them in the pool — **Validated** (Phase 2, Plan 02-02 dual-query merge)

### Ranking Engine

- [x] **RANK-01**: On first load with no saved rankings for this user, games are assigned random initial positions distributed across the bell-curve tiers — **Validated** (Phase 2, Plan 02-02)
- [x] **RANK-02**: App presents two randomly selected games from the pool; user picks the one they prefer — **Validated** (Phase 2, Plan 02-03)
- [x] **RANK-03**: When the chosen game was ranked lower, it takes the loser's exact decimal rating; every game between the winner and loser in ranked order shifts down one spacing step — **Validated** (Phase 1 engine; Phase 2 wiring)
- [x] **RANK-04**: User can skip a comparison ("Too close to call"); the pair is re-queued for a later round — **Validated** (Phase 2, Plan 02-03)
- [x] **RANK-05**: App displays a comparison count (current session and total lifetime) — **Validated** (Phase 2, Plan 02-03)
- [x] **RANK-06**: Rankings follow a bell-curve tier distribution with weights 2/6/12/18/24/30/10/5/3/3 (normalized to 100%) for tiers 10 through 1 — **Validated** (Phase 1, Plan 01-02)
- [x] **RANK-07**: Each game has a unique decimal rating with exactly 2 decimal places; no two games share a rating — **Validated** (Phase 1, Plan 01-02; uniqueness guaranteed up to 373 games)
- [x] **RANK-08**: Tier N covers the range [N.00, (N-1).01] — tier 9 = 9.00 down to 8.01; tier 1 = 1.00 down to 0.01 (clamped to 1.00 if BGG rejects sub-1.0 values) — **Validated** (Phase 1, Plan 01-02)
- [x] **RANK-09**: Decimal values within a tier are equally spaced across the full available range; ratings stored as integers internally (e.g. `801` = 8.01) to eliminate floating-point precision errors — **Validated** (Phase 1, Plan 01-02)
- [x] **RANK-10**: System validates tier capacity before initializing; hard ceiling is 990 games; user sees a clear error if collection exceeds this — **Validated** (Phase 2, Plan 02-02)

### Refresh & Redistribution

- [x] **REFRESH-01**: User can trigger a manual refresh to redistribute all rankings, rebalancing tier allocations for the current collection size while preserving relative game order — **Validated** (Phase 2, Plan 02-03)

### BGG Sync

- [x] **SYNC-01**: User can manually trigger a batch sync to push all current decimal ratings to BGG as star ratings — **Validated** (Phase 3; write path fixed in Phase 3.1)
- [x] **SYNC-02**: App shows progress during sync (e.g. "Syncing 47 / 200...") with per-request throttling (1000ms between writes) to avoid BGG rate limits — **Validated** (Phase 3.1; throttle changed from random 200–500ms to fixed 1000ms)
- [x] **SYNC-03**: If sync is interrupted (page reload, session expiry), the app can resume from where it left off on next attempt — **Validated** (Phase 3.1 — dirtyGameIds persisted; only remaining dirty IDs re-synced)

### Display

- [ ] **DISP-01**: BGG thumbnail (cover art) is shown for each game during head-to-head comparison picks — **Deferred** (Phase 4, not yet built)
- [ ] **DISP-02**: After picking a winner, the app shows a callout if the chosen game moved up significantly in the rankings — **Deferred** (Phase 4, not yet built)

### Persistence

- [x] **PERSIST-01**: Current rankings are saved to localStorage after every comparison so they survive page reload — **Validated** (Phase 2, Plan 02-02 Zustand persist)
- [x] **PERSIST-02**: Stored rankings load automatically on return visits in the same browser; if the stored username differs from the logged-in user, the stored rankings are discarded — **Validated** (Phase 2, Plan 02-02 PERSIST-02 guard)
