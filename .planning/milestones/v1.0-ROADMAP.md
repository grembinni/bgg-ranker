## Milestone Summary

**Key Accomplishments (v1.0 increment over v0.9):**
1. BGG cover art (192px) shown on every comparison card — thumbnail URL from Phase 2's parseCollectionXml, ternary img/placeholder in GameCard
2. Upset callout ("Game moved up N spots") — `lastUpset` field in store, 5s module-level timer, amber callout in ComparisonView
3. Hamburger menu consolidates Sync/Refresh/Logout — cleans comparison screen from 3 direct buttons to a single menu
4. PERSIST-02 auto-resume: `login()` guard checks `rankingsUsername + ratings + games` before deciding to call `continueSession()` vs `fetchCollection()` — unsynced progress survives logout/re-login
5. Firebase Function routing fix: `req.path` replaces `req.query['path']` — production API calls now reach the correct BGG endpoint
6. Logout action: clears session without touching rankings; user can re-login and resume instantly

**Decimal Phases:**
- None in v1.0 increment (Phase 3.1 was v0.9)

**Key Decisions:**
- `lastUpset` excluded from `partialize` — session-only; cleared on page reload (intentional)
- upsetTimer is module-level (not Zustand state) — prevents serialization to null in persist, avoids timer leaks
- Pre-upset positions computed before `applyUpset()` — computing after gives wrong positions
- PERSIST-02 guard lives in `login()`, not `fetchCollection()` — `fetchCollection` always fetches when called directly
- `logout()` calls `cancelSync()` (not `resetForNewUser()`) — preserves rankings for instant re-login
- Phase 5 (Firebase deploy) deferred to v1.1 — app is feature-complete; production hosting is a separate concern
