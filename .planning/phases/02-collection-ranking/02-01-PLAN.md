# Plan 02-01: Wave 0 Test Scaffolds (Tests-First Foundation)

## Phase Goal

**As a** BGG user, **I want to** enter my BGG username and rank my owned games head-to-head with progress saved locally, **so that** I can build a ranked list of my collection that reflects my actual preferences.

<objective>
Create the Wave 0 test scaffolds for both `src/api/bggClient.ts` and `src/store/store.ts` with red (failing) tests that codify every Phase 2 behavior contract: COLL-01 XML parse + 202 polling + HTML-200 guard + 0-game guard, COLL-03 dedup, RANK-01 initial seed, RANK-02 pair selection, RANK-03 upset via `applyUpset`, RANK-04 skip queue drain order, RANK-05 dual counter increment, REFRESH-01 redistribute preserves order, PERSIST-01 ratings appear in mock storage after pick, PERSIST-02 stored-username guard + discard path, and the 990/991-game tier capacity boundary. Tests are written against the not-yet-implemented modules so the next two plans have automated verification from their first commit. After this plan: `npm test` reports the new test files as failing (RED) — that is the expected and correct outcome of Wave 0.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → URL | BGG username typed by user is concatenated into a query-string URL — untrusted text crosses into a fetch URL |
| BGG XML → app state | External XML response is parsed and used to seed ratings/persistence — untrusted external input |
| localStorage → app state | Persisted JSON is rehydrated on app load — could contain stale or tampered data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | URL construction in `fetchCollection` | mitigate | Test that `fetchCollection` passes username through `encodeURIComponent` before concatenation; assert URLs containing `&`, ` `, and `?` in the username are percent-encoded |
| T-02-02 | Denial of Service | `poll202Loop` infinite-retry abuse | mitigate | Test enforces `MAX_RETRIES = 8` and throws on the 9th attempt; no unbounded loop |
| T-02-03 | Spoofing | BGG returns HTML error page with HTTP 200 | mitigate | Test asserts `poll202Loop` throws when response body starts with `<html` (case-insensitive); does not feed HTML into XML parser |
| T-02-04 | Information Disclosure | 0-game write to localStorage destroys prior rankings | mitigate | Test asserts `fetchCollection` action sets `view: 'error'` and does NOT mutate `ratings` when parsed game count is 0 |
| T-02-05 | Tampering | Stale localStorage rankings used for wrong user | mitigate | Test asserts `fetchCollection` discards `ratings` when persisted `rankingsUsername` differs from entered username (PERSIST-02 guard) |
</threat_model>
