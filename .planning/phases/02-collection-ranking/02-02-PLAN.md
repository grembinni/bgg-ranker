# Plan 02-02: Vertical Slice — BGG Fetch → Store → Username Entry UI

## Phase Goal

**As a** BGG user, **I want to** enter my BGG username and rank my owned games head-to-head with progress saved locally, **so that** I can build a ranked list of my collection that reflects my actual preferences.

<objective>
Deliver the first end-to-end vertical slice of Phase 2: the user can type a BGG username, click "Load Collection", see a loading view while BGG's 202 polling completes, and arrive at a `view: 'comparison'` state with a fully seeded `ratings` map persisted to localStorage. On a return visit with the same username, the continue-or-refetch prompt (D-10) appears. On a return visit with a different username, the stored rankings are discarded and a fresh seed is created. Collections over 990 games fail loudly with the exact error copy from UI-SPEC; 0-game results never destroy prior rankings. This plan implements `src/api/bggClient.ts`, `src/store/store.ts`, three of the four views (`UsernameEntry`, `CollectionLoading`, `ErrorDisplay`), and the view router in `App.tsx`. The Comparison view itself is Plan 02-03 — but at the end of this plan, the store has already selected `currentPair` and the user reaches the comparison view; clicking the (yet-unbuilt) ComparisonView is what Plan 02-03 wires up. By the end of this plan, the bggClient and store tests from Plan 02-01 all turn GREEN.
</objective>
