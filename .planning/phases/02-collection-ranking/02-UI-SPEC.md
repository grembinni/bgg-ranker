# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2: Collection & Ranking.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Source of truth: D-01 through D-17 in 02-CONTEXT.md.
> Phase 4 is the polish phase — this contract is intentionally minimal.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none — text labels only in Phase 2 |
| Font | system-ui (browser default via Tailwind v4 preflight) |

**Rationale:** D-04 locks "clean utility UI — functional Tailwind styling, no design polish." No shadcn, no component library, no icon library for this phase. All styling is pure Tailwind v4 utility classes applied directly in JSX.

---

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline spacing (not used in Phase 2 — no icons) |
| sm | 8px | Label-to-input gap, button padding vertical, card internal gap between metadata lines |
| md | 16px | Card internal padding, form field gap, default element spacing |
| lg | 24px | Gap between the two game cards on the comparison screen |
| xl | 32px | Section padding inside each view, gap between card area and action buttons |
| 2xl | 48px | Top/bottom padding on the loading and entry views |
| 3xl | 64px | Not used in Phase 2 |

Exceptions:
- Touch/click targets on primary Pick buttons: minimum 44px height (accessibility — WCAG 2.5.5 target size). Achieved via `min-h-[44px]` on button elements.
- Skip and Refresh secondary buttons: minimum 36px height (not primary actions; desktop-first utility app).

---

## Typography

All sizes use Tailwind v4 utility classes directly. No custom font — `font-sans` resolves to the OS system-ui stack.

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 16px | 400 (regular) | 1.5 | `text-base font-normal leading-normal` |
| Label | 14px | 400 (regular) | 1.4 | `text-sm font-normal leading-snug` |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold leading-tight` |
| Display | 28px | 600 (semibold) | 1.2 | `text-2xl font-semibold leading-tight` |

**Scale constraint:** Exactly 4 sizes (14, 16, 20, 28px). Exactly 2 weights (400 regular, 600 semibold).

**Usage map:**
- Display (28px/600): App title "BGG Ranker" on the Username Entry view only.
- Heading (20px/600): Game name on each comparison card.
- Body (16px/400): Counter text, form labels, loading message, error message, prompt text, year/rank metadata.
- Label (14px/400): Secondary button labels (Skip, Refresh), card rank position line ("#47 of 200"), year published.

## Color

Light-mode only. No dark mode in Phase 2.

| Role | Value | Tailwind Class | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | #ffffff / #f9fafb | `bg-white` / `bg-gray-50` | Page background (`bg-gray-50`), card surfaces (`bg-white`) |
| Secondary (30%) | #e5e7eb | `bg-gray-200` / `border-gray-200` | Card borders, dividers, input borders |
| Accent (10%) | #2563eb | `bg-blue-600`, `text-blue-600` | Primary Pick buttons only |
| Destructive | #dc2626 | `text-red-600`, `border-red-200` | Error state text and error container border only |

**Accent reserved for:** The two "Pick this game" primary buttons on the comparison screen, and the submit button on the Username Entry form. Nothing else uses blue. Counter text, labels, and headings are all `text-gray-900` or `text-gray-500`.

**Contrast check (pre-declared):**
- `bg-blue-600` with `text-white` button label: 4.54:1 — passes WCAG AA for normal text.
- `text-gray-900` on `bg-white`: 21:1 — passes AAA.
- `text-gray-500` on `bg-white`: 4.48:1 — passes AA for body text.
- `text-red-600` on `bg-white`: 4.48:1 — passes AA.

**Note for Phase 4:** This palette is a placeholder for a polished palette. Phase 4 may replace gray-50/gray-200 with a warm neutral or custom theme. The blue accent is a provisional default.

## View Layouts

Three views driven by `store.view` conditional rendering in App.tsx (D-01, D-02).

### View 1: Username Entry

```
┌─────────────────────────────────────────┐
│  (2xl vertical padding top)             │
│                                         │
│  [Display] BGG Ranker                   │
│                                         │
│  [Body] Enter your BGG username to      │
│  load your collection.                  │
│                                         │
│  [Label] BGG Username                   │
│  [Input text field]                     │
│                                         │
│  [Primary Button] Load Collection       │
│                                         │
│  ── (shown only if stored session) ──   │
│  [Body] Found 142 ranked games from     │
│  your last session.                     │
│  [Secondary] Continue ranking           │
│  [Secondary] Re-fetch collection        │
│                                         │
│  (2xl vertical padding bottom)          │
└─────────────────────────────────────────┘
```

- Container: `max-w-sm mx-auto px-4 py-12` (centered, narrow column)
- Title and subtitle: stacked with `gap-y-2`
- Form: `mt-8 flex flex-col gap-4`
- Input: `w-full border border-gray-200 rounded px-3 py-2 text-base`
- Continue-or-refetch prompt: inline block below primary button, `mt-6 pt-6 border-t border-gray-200`

### View 2: Collection Loading

```
┌─────────────────────────────────────────┐
│  (2xl vertical padding)                 │
│                                         │
│  [Heading] Loading collection…          │
│                                         │
│  [Body] Fetching games from BGG.        │
│  This may take a moment.                │
│                                         │
│  [Loading indicator]                    │
│                                         │
│  [Body] {loadingMessage}                │
│  e.g. "Retrying… (attempt 3 of 8)"     │
│                                         │
└─────────────────────────────────────────┘
```

- Container: `max-w-sm mx-auto px-4 py-12 text-center`
- Loading indicator: CSS `animate-spin` on a 24px border-based spinner (pure Tailwind, no library). Exact class: `w-6 h-6 border-2 border-gray-200 border-t-blue-600 rounded-full animate-spin mx-auto`
- `loadingMessage` from store: updates as poll loop progresses. Format defined in Copywriting section.

### View 3: Comparison Screen

```
┌─────────────────────────────────────────────────────┐
│ HEADER                                              │
│ [Body] {username}        [Body] 12 / 847 total      │
├─────────────────────────────────────────────────────┤
│                                                     │
│ CARDS ROW                                           │
│ ┌──────────────────┐   ┌──────────────────┐        │
│ │ [Heading] Game A │   │ [Heading] Game B │        │
│ │ [Label] (2021)   │   │ [Label] (2019)   │        │
│ │ [Label] #47/200  │   │ [Label] #102/200 │        │
│ │                  │   │                  │        │
│ │ [Pick Button]    │   │ [Pick Button]    │        │
│ └──────────────────┘   └──────────────────┘        │
│                                                     │
│ ACTIONS ROW (below cards)                           │
│ [Skip] [Refresh]                                    │
│                                                     │
└─────────────────────────────────────────────────────┘
```

- Outer container: `max-w-2xl mx-auto px-4 py-8`
- Header: `flex justify-between items-center mb-8 text-base text-gray-700`
- Cards row: `grid grid-cols-2 gap-6` (lg: gap-6; the 24px declared above)
- Each card: `bg-white border border-gray-200 rounded-lg p-4 flex flex-col gap-2`
- Card game name: `text-xl font-semibold text-gray-900 leading-tight`
- Card year: `text-sm text-gray-500`
- Card rank position: `text-sm text-gray-500`
- Pick button: full-width inside card, `mt-auto w-full min-h-[44px] bg-blue-600 text-white text-base font-semibold rounded px-4 py-2`
- Actions row: `flex gap-4 justify-center mt-8`
- Skip button: `px-6 py-2 border border-gray-200 rounded text-sm text-gray-700`
- Refresh button: `px-6 py-2 border border-gray-200 rounded text-sm text-gray-700`

Displayed inline in the same centered column as the entry view.

```
┌─────────────────────────────────────────┐
│  [Error container]                      │
│  border-red-200, rounded, p-4           │
│                                         │
│  [Heading] Something went wrong         │
│                                         │
│  [Body/red] {errorMessage}              │
│                                         │
│  [Secondary Button] Try again           │
│                                         │

```

- Container: `max-w-sm mx-auto px-4 py-12`
- Error box: `border border-red-200 rounded-lg p-4 bg-white`
- Error heading: `text-xl font-semibold text-gray-900 mb-2`
- Error message: `text-base text-red-600`
- Try again button: same style as secondary buttons

### View 3: Comparison Screen

| Element | Copy |
|---------|------|
| Header — username | {username} |
| Header — session counter | Session: {n} |
| Header — total counter | Total: {n} |
| Header — combined counter | {session} this session · {total} total |

**Counter format decision (RANK-05):** Display as "{session} this session · {total} total" in a single line in the header. Example: "3 this session · 847 total". This satisfies RANK-05 (both session and total counts visible) without requiring two separate UI regions.

|----------------|------|
| Error view heading | Something went wrong |
| BGG API timeout (202 exhausted) | BGG didn't respond in time. Check your username and try again. |
| BGG API HTTP error | BGG returned an error (HTTP {status}). Try again in a moment. |

| 0-game result | No board games found for "{username}". Check your BGG username and try again. |

## Accessibility Baseline

Minimum requirements for Phase 2 (Phase 4 will audit fully):

- All buttons have visible focus rings (`outline-2 outline-offset-2 outline-blue-600`)
- Pick buttons have minimum 44px height (`min-h-[44px]`)
- Form input has `<label>` element associated via `htmlFor`/`id`
- Loading view has `role="status"` and `aria-live="polite"` on the message container
- Error view has `role="alert"` on the error container
- Spinner has `aria-hidden="true"` and a visually-hidden text label: "Loading…"
- Color is not the sole differentiator for any state (error also uses `border-red-200` shape cue, not just red text)

## Explicitly Out of Scope for Phase 2

Per D-04 and Phase 4 being the polish phase:

- No thumbnail/cover art images (D-07 — stored but not displayed)
- No CSS transitions or animations on state changes (D-04)
- No box shadows or decorative gradients
- No dark mode
- No responsive/mobile breakpoints (desktop-first utility app; mobile is Phase 4+ concern)
- No upset callout component (DISP-02 — Phase 4)
- No ranked list view (DISP-V2-01 — v2)
- No skeleton loaders (plain spinner is sufficient)
- No toast notifications
- No custom fonts (system-ui stack)
