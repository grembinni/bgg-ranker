# Phase 3.1: Sync Repair — Context

**Gathered:** 2026-05-25
**Status:** Ready for planning
**Inserted between:** Phase 3 (Auth & BGG Sync) and Phase 4 (Display Polish)

<domain>
## Phase Boundary

Phase 3 built the full sync pipeline but "Sync to BGG" surfaces a generic "Sync failed. Please try again." error in practice. This phase diagnoses the failure, fixes the write path, and improves how the app tracks which games actually need syncing.

**Phase 3.1 ends when:**
- Clicking "Sync to BGG" successfully writes ratings to BGG (confirmed via BGG profile after sync)
- The proxy correctly forwards write requests to BGG with a valid session regardless of whether `proxySession` is populated
- The SyncingView shows the actual HTTP status or reason when a write fails (not just a generic message)
- The app only syncs games whose ratings actually changed (not a full resend on every comparison)
- Sync throttle is 1 second between writes

**Phase 3.1 does NOT include:**
- Display polish / cover art (Phase 4)
- Firebase production deploy (Phase 5)
- Any new UI views or flows

</domain>

<decisions>
## Implementation Decisions

### D-01: Write-path failure mode
The "Sync failed" error is caused by a combination of factors:
- `proxySession` (closure variable in Vite server process) is null when the write fires — either the dev server restarted after login, or no login occurred in the current server session
- When `proxySession` is null, the proxy strips `X-BGG-Session` but injects no Cookie → write request reaches BGG unauthenticated → BGG returns 401/403
- The current `bggRateGame` throws on any non-2xx without logging the actual status, so the UI shows a generic error

### D-02: Proxy session fallback
When `proxySession` is null, the proxy should fall back to constructing a Cookie from the `X-BGG-Session` header value: `Cookie: SessionID=<value>`. The full three-cookie string (SessionID + bggusername + bggpassword) is only guaranteed from a live login response; `SessionID` alone is sufficient for the geekrating write endpoint.

### D-03: `ajax=1` in write body
Some BGG endpoints suppress HTML redirect responses when `ajax=1` is included in the POST body. Adding it to the `bggRateGame` request is low-risk and may prevent unexpected HTML responses being mis-classified as errors.

### D-04: Dirty tracking replaces syncedGameIds clearing
Current approach: every comparison, reorder, or markUnplayed clears `syncedGameIds`, causing the next sync to re-send ALL games. New approach: maintain a `dirtyGameIds: string[]` set that tracks exactly which game IDs have had rating changes since the last sync. Only those are sent.

Semantics comparison:
- `syncedGameIds` (old): positive exclusion — "already sent; skip"
- `dirtyGameIds` (new): positive inclusion — "has changed; send this"

`dirtyGameIds` is persisted to localStorage, so partial syncs survive page reloads.

### D-05: Dirty marking rules per action
- `pick(winnerId)` — after `applyUpset`, compare old vs new ratings; mark every game whose integer rating changed as dirty
- `markUnplayed(gameId)` — mark gameId dirty (rating=0 must be written to BGG)
- `reorderRankedList(newOrder)` — `initializeRankings` changes all ratings; mark all games in the new order dirty
- `moveUnplayedToRanked(gameId, rank)` — same full redistribution; mark all newly-rated games dirty
- `refresh()` — full redistribution; mark all rated games dirty
- `login() / fetchCollection()` — initial seed; all rated games are dirty until first sync

### D-06: Sync button condition change
Old: `!sessionId || (comparisonsTotal === comparisonsAtLastSync && !hasUnsyncedUnplayed)`
New: `!sessionId || dirtyGameIds.length === 0`
`dirtyGameIds` is the single source of truth for "is there anything to sync?"

### D-07: `beforeunload` guard
Old: `comparisonsTotal > comparisonsAtLastSync`
New: `dirtyGameIds.length > 0`
More accurate — fires exactly when there are unsaved changes, not when a comparison happened without a subsequent sync.

### D-08: `comparisonsAtLastSync` retained but secondary
`comparisonsAtLastSync` stays in the store for historical reference but is no longer the primary sync gate. `completeSyncAll` still updates it. Remove from `ComparisonView` sync-button calculation.

### D-09: Throttle
Change from `200 + Math.floor(Math.random() * 300)` ms to a fixed `1000` ms.

</decisions>
