### Human Verification Required

5 items require runtime/visual verification:

#### 1. End-to-End Sync Succeeds (ROADMAP SC-1)

**Test:** Log in with valid BGG credentials. Make 3–5 comparisons. Click "Sync to BGG". Wait for SyncingView to complete.
**Expected:** No "Sync failed" error appears. BGG profile page (boardgamegeek.com/user/USERNAME/ratings) shows updated star ratings matching the app's decimal values.
**Why human:** Requires a live BGG session and network traffic to boardgamegeek.com. Cannot be verified by static code analysis.

#### 2. Proxy Fallback Cookie Path (ROADMAP SC-2)

**Test:** Log in successfully. Stop the Vite dev server. Restart it (`npm run dev`). WITHOUT logging in again, make a comparison and click "Sync to BGG".
**Expected:** Sync succeeds — the X-BGG-Session header sent by the client is converted to `SessionID=<value>` cookie by the proxy and the write reaches BGG authenticated.
**Why human:** The `proxySession` null code path only triggers after a dev server restart with the session token still held in the browser. This runtime process-lifetime behavior cannot be tested statically.

#### 3. Dirty Set Size in SyncingView (ROADMAP SC-3)

**Test:** Start with a freshly-loaded collection. Make exactly 3 comparisons. Click "Sync to BGG". Watch the counter in SyncingView.
**Expected:** syncTotal shows a small number (typically 6–12 games, reflecting 2–4 changed IDs per comparison) rather than the full collection size (e.g. 200).
**Why human:** Requires visual inspection of SyncingView's progress counter during a live sync. The exact count depends on how many games `applyUpset` shifts per comparison.

#### 4. Sync Button Disabled After Sync

**Test:** Complete a full sync to BGG. Observe the "Sync to BGG" button state in ComparisonView header.
**Expected:** Button is disabled (opacity-50, cursor-not-allowed) — `dirtyGameIds` is empty after all `markGameSynced()` calls drain it.
**Why human:** Requires visual inspection of button state after a live sync.

#### 5. Sync Button Re-Enables After Pick

**Test:** After a full sync (button disabled), make one comparison by picking a game.
**Expected:** "Sync to BGG" button becomes enabled — `pick()` adds changed game IDs to `dirtyGameIds`, reactive update re-renders the button.
**Why human:** Requires visual verification that Zustand reactivity propagates `dirtyGameIds` changes to the button's `disabled` attribute.
