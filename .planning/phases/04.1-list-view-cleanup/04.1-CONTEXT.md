<decisions>
## Implementation Decisions

### Navigation Model

- **D-01:** ComparisonView action bar gets two buttons: `☰ Ranked list` (existing, adds hamburger icon prefix) and `⊞ Grid view` (new, grid icon). Both route directly from the comparison screen.
- **D-02:** Store view union gains a new `'ranked-grid'` view state. `showRankedGrid()` action sets it; `backToComparison()` is reused for the "← Back" button.
- **D-03:** RankedListView is **unchanged** in navigation behavior — keeps its existing "← Back" button. No hamburger added to the text list view.
- **D-04:** RankedGridView header mirrors RankedListView exactly: title left, "← Back" button right. No hamburger in the grid view.

### Grid Layout

- **D-05:** `grid grid-cols-10 gap-1` with each cell as `aspect-square overflow-hidden rounded`. Tailwind grid — 10 columns fixed; cells shrink proportionally on narrow screens (no breakpoints for the grid itself).
- **D-06:** Cells show **thumbnail only** — no rank number overlay, no name label, no tooltip. Pure image grid. Gray placeholder (`bg-gray-100`) for games without a thumbnail, consistent with GameCard pattern.
- **D-07:** Page size: 100 games (10×10). Pagination shifts by 50 games ("← Prev 50" / "Next 50 →" buttons). Header shows current range, e.g., "Rankings 1–100 of 312".

### Grid Drag-and-Drop

- **D-08:** DnD uses `rectSortingStrategy` from `@dnd-kit/sortable` (already installed). Grid items are sortable within the visible 100-game page only — no cross-page drag.
- **D-09:** On `dragEnd`, immediately call `reorderRankedList(newFullOrder)` where `newFullOrder` is the page slice merged back into the full ordered list. Same optimistic-then-commit pattern as RankedListView.
- **D-10:** DnD triggers ratings recalculation and `dirtyGameIds` update via the existing `reorderRankedList` store action — no new store action needed.

### Image Preloading

- **D-11:** In-memory URL set via a React `useRef<Set<string>>` (not Zustand — session-only, no persistence needed). Tracks which thumbnail URLs have been loaded by the browser.
- **D-12:** Preload strategy: **eagerly on mount** (all 100 visible thumbnails) and **on page advance** (incoming 50 before flipping the page). Uses `new Image()` constructor to trigger browser caching. When a URL is already in the ref set, skip it.
- **D-13:** Preloading is fire-and-forget — no loading state, no spinner. If an image hasn't loaded by render time, the `<img>` falls back to the gray placeholder via `onError`.

### Dirty-Flag Test Coverage

- **D-14:** `moveUnplayedToRanked` already adds `changedIds` to `dirtyGameIds` (implemented in Phase 3.1). Phase 4.1 adds a test asserting that after calling `moveUnplayedToRanked`, the inserted game's ID (and any games whose ratings shifted) appears in `dirtyGameIds`. This is a coverage gap, not a code change.

### Claude's Discretion

- Drag handle design for grid cells (if any): no explicit instruction — Claude may omit drag handles since the entire cell is the drag target in a grid (full-cell drag is standard for image grids).
- Pagination button placement (above grid, below grid, or both): Claude's choice — keep it consistent with grid density.

</decisions>

<specifics>
## Specific Ideas

- Hamburger icon on the Ranked List button in ComparisonView is a **visual affordance** — it tells users before they click that this view is a flat list (as opposed to the grid). The icon prefix (`☰`) should appear before the button text.
- Grid button icon should be a grid/squares icon — can use a CSS grid of four squares (⊞ or similar Unicode) or an SVG if a cleaner icon is needed.
- The `useRef<Set<string>>` for image preloading lives inside `RankedGridView` component — not a shared hook, not Zustand. It resets when the component unmounts (session-scoped naturally).
- Pagination range display: "Rankings 51–150 of 312" format in the header — gives user clear orientation in the full list.

</specifics>
