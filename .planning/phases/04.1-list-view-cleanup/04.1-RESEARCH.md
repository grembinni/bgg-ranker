### Pattern 1: Grid DnD with rectSortingStrategy

**What:** Same `DndContext` + `SortableContext` + `useSortable` + `arrayMove` wiring as `RankedListView`, but with `rectSortingStrategy` for 2D grid ordering.
**When to use:** Any time items are arranged in a grid where movement is non-linear (not just up/down).

```typescript
// Source: @dnd-kit/sortable package, verified installed at 10.0.0 [VERIFIED: codebase npm list]
// Pattern mirrors RankedListView.tsx lines 103–111 with strategy swap

import {
  SortableContext,
  useSortable,
  rectSortingStrategy,   // <-- replaces verticalListSortingStrategy
  arrayMove,
} from '@dnd-kit/sortable'

// In component:
<SortableContext items={pageSlice} strategy={rectSortingStrategy}>
  <div className="grid grid-cols-10 gap-1">
    {pageSlice.map(id => <SortableGridCell key={id} id={id} />)}
  </div>
</SortableContext>

// handleDragEnd merges page back into full order:
function handleDragEnd(event: DragEndEvent) {
  const { active, over } = event
  if (!over || active.id === over.id) return
  const oldIndex = pageSlice.indexOf(active.id as string)
  const newIndex = pageSlice.indexOf(over.id as string)
  const newPage = arrayMove(pageSlice, oldIndex, newIndex)
  const newFullOrder = [
    ...sortedFromStore.slice(0, pageOffset),
    ...newPage,
    ...sortedFromStore.slice(pageOffset + pageSlice.length),
  ]
  setLocalOrder(newFullOrder)
  reorderRankedList(newFullOrder)
}
```

### Pattern 2: Session Image Preloading with useRef

**What:** Track which thumbnail URLs have been preloaded in a `useRef<Set<string>>` that persists for the component's lifetime. Use `new Image()` to trigger browser HTTP cache population.
**When to use:** When navigating between pages of thumbnails and wanting to avoid re-fetching on return.

```typescript
// Source: browser native API + React useRef [ASSUMED: standard React pattern]
const preloadedUrls = useRef<Set<string>>(new Set())

function preloadImages(urls: string[]) {
  for (const url of urls) {
    if (!url || preloadedUrls.current.has(url)) continue
    preloadedUrls.current.add(url)
    const img = new Image()
    img.src = url
  }
}

// On mount and on page advance:
useEffect(() => {
  const visible = pageSlice.map(id => games[id]?.thumbnail).filter(Boolean)
  preloadImages(visible.map(normalizeUrl))
  // Preload incoming 50 if paging forward
  if (pageOffset + 100 < sortedFromStore.length) {
    const incoming = sortedFromStore
      .slice(pageOffset + 50, pageOffset + 150)
      .map(id => games[id]?.thumbnail)
      .filter(Boolean)
    preloadImages(incoming.map(normalizeUrl))
  }
}, [pageOffset])
```

### Anti-Patterns to Avoid

- **Cross-page DnD:** Do not attempt to drag items from one page to another. `SortableContext` wraps only `pageSlice` (the current 100 items). Items outside the page are not registered with dnd-kit and cannot be drag targets. (D-08)
- **Persisting page offset:** `pageOffset` is `useState` inside `RankedGridView`. It must NOT go into Zustand or localStorage — it is pure session UI state that resets on component unmount. (D-11 analog)
- **localOrder vs sortedFromStore confusion:** `localOrder` (optimistic DnD state) covers the full ordered ID list, not just the page slice. The page slice is derived by slicing `localOrder ?? sortedFromStore`. Always merge the reordered page back into `localOrder` (full list), then pass the full list to `reorderRankedList`.
- **Float ratings in grid rendering:** Never divide by 100 for comparisons or reordering. Only divide by 100 for display text (not needed in thumbnail-only D-06 cells).
- **New Image() in render:** The preload calls must be inside `useEffect`, never during render. Constructing `Image` in render body runs on every re-render and defeats caching.

## Common Pitfalls

### Pitfall 1: localOrder tracks full list, page slice is derived
**What goes wrong:** Developer stores only the page slice in `localOrder`, then calls `reorderRankedList(localOrder)` directly — this drops all games outside the current page from the ratings map.
**Why it happens:** The page slice is the visible data, so it feels like the natural unit to track.
**How to avoid:** Always maintain `localOrder` as the complete ordered ID list (same length as `sortedFromStore`). Derive the page view with `.slice(pageOffset, pageOffset + 100)`. On drag end, merge the reordered page back into the full list before calling `reorderRankedList`.
**Warning signs:** After a drag, `Object.keys(ratings).length` drops to ≤ 100 games.

### Pitfall 2: useRef Set does not trigger re-render
**What goes wrong:** Trying to conditionally render a loading state or spinner based on `preloadedUrls.current.size` — this will never update the UI because ref mutations don't trigger re-renders.
**Why it happens:** `useRef` and `useState` look similar but behave differently.
**How to avoid:** D-13 explicitly prohibits a loading state. Use `onError` on `<img>` for fallback; never read the ref during render for conditional display.
**Warning signs:** Any `preloadedUrls.current.size` read outside of a `useEffect`.

### Pitfall 3: rectSortingStrategy expects 2D layout measured at render time
**What goes wrong:** If the grid cells have no measured dimensions (e.g., display:none on mount), the strategy may sort incorrectly.
**Why it happens:** `rectSortingStrategy` uses `getBoundingClientRect` to determine grid positions. Elements must be visible and sized.
**How to avoid:** Ensure `aspect-square` + `grid grid-cols-10` are applied. Don't conditionally hide the grid while DnD context is active.
**Warning signs:** Items snap to wrong positions or rearrange non-intuitively on drop.

### Pitfall 4: Pagination offset out of bounds after store update
**What goes wrong:** A drag moves games, ratings recalculate, and the full sorted order shifts. If `pageOffset` was at 250 for a 300-game collection, after a reorder the collection might still be 300 games but the offset is valid — however, if games are removed (e.g., by `markUnplayed` from RankedListView while grid is open), `pageOffset` could point past the end.
**Why it happens:** `pageOffset` is independent of the store's `ratings` length.
**How to avoid:** Clamp `pageOffset` when deriving the page: `const safeOffset = Math.min(pageOffset, Math.max(0, sortedFromStore.length - 1))`. Also reset to 0 if `sortedFromStore.length - pageOffset < 1`.
**Warning signs:** Empty grid page or RankedGridView shows "Rankings 251–350 of 240".

### Pitfall 5: D-14 test gap may already be covered
**What goes wrong:** Phase plan allocates work to write `moveUnplayedToRanked` dirty-flag tests, but those tests already exist in `store.test.ts` under `describe('moveUnplayedToRanked() dirty tracking (SYNC-03)')`.
**Why it happens:** CONTEXT.md D-14 says "Phase 3.1 implemented it; Phase 4.1 adds coverage" — but Phase 3.1 already added two tests for this exact behavior.
**How to avoid:** The planner should verify coverage by reading lines 983–1010 of `store.test.ts`. If the existing tests cover "game ID appears in dirtyGameIds after moveUnplayedToRanked", D-14's work is done. The plan should note this as a verification step, not a new-code step.
**Warning signs:** Duplicate test describe blocks.
