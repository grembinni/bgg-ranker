<decisions>
## Implementation Decisions

### Universal header
- **D-01:** A single header component renders across all four game views — comparison ("vs"), ranked-list, ranked-grid, unplayed-list. Currently each view hand-rolls its own header; this replaces all of them.
- **D-02:** Header contents, left to right: hamburger menu (☰) — Sync to BGG, Refresh rankings, **Unplayed (new menu item — moved out of the button row)**, Logout · then "{sessionComparisons} this session · {comparisonsTotal} total" · then three view-switch icons: vs, list, grid · then `{sessionUsername}`.
- **D-03:** Icons: reuse existing glyphs — ☰ for list, ⊞ for grid (matches current ComparisonView button glyphs). The comparison/"vs" icon is new — no existing glyph to reuse; planner picks a simple glyph or "VS" text (e.g. ⚔ or plain "VS") consistent with the other two.
- **D-04:** Unplayed view gets the same universal header treatment as the other three (hamburger/counts/icons/username), even though the user didn't name it explicitly when listing views — confirmed explicitly in discussion. Its current standalone "Unplayed (N games)" title + "← Back" header is replaced.
- **D-05:** Back buttons are removed from RankedListView, RankedGridView, and UnplayedListView now that the universal header (with vs/list/grid icons + hamburger) provides navigation. `backToComparison()` store action stays — it's now wired to the "vs" header icon instead of a per-view back button.

### ComparisonView cleanup
- **D-06:** Remove the "☰ Ranked list", "⊞ Grid view", and "Unplayed (N)" buttons from the row below the game cards — navigation now lives entirely in the universal header (list/grid icons + hamburger's Unplayed item).
- **D-07:** Move the Skip button to the right of the two game cards (currently it's centered in a button row below the cards, alongside the now-removed nav buttons). New layout: game cards + Skip button in a single row.
- **D-08:** Skip button styling: red (currently neutral gray/white bordered button), full height to match the GameCard column height ("vertically as high as the game selections"), same width as its current styling (`px-6` horizontal padding — don't change width).
- **D-09:** The upset callout (`lastUpset`) stays as-is, positioned as it is today (between the cards and the button row).

### Default view
- **D-10:** Grid becomes the default view everywhere the store currently sets `view: 'comparison'` as a landing/reset state — this includes: after login/collection load (store.ts lines ~257, ~293), after sync completes (~539, ~554), and after a session-expiry/401 reset (~569). All of these become `view: 'ranked-grid'` instead. (User explicitly chose "all of them" over the narrower "initial landing only" option.)
- **D-11:** `backToComparison()` itself is unchanged — it still sets `view: 'comparison'` on demand (wired to the header's "vs" icon click). Only the *automatic* transitions listed in D-10 change to grid.

### Claude's Discretion
- Exact glyph/label for the "vs" header icon (D-03) — pick something visually consistent with ☰/⊞.
- Whether the currently-active view's icon in the header gets a highlighted/disabled state — not discussed; reasonable default (e.g. subtle active-state styling) is fine.
- Exact flex/grid layout mechanics for placing Skip beside the two GameCards (D-07/D-08) — three-column layout, flex row, etc. — implementation detail.
- Where within the header the hamburger menu opens/closes (mouse-enter/leave with 150ms close delay) — reuse the existing pattern from ComparisonView's current hamburger implementation.

</decisions>

## Existing Code Insights

### Reusable Assets
- ComparisonView's existing hamburger menu implementation (state, 150ms close-delay timer, Sync/Refresh/Logout items) — the pattern to extend with a new "Unplayed" item and extract into the shared header component
- `showRankedList()`, `showRankedGrid()`, `showUnplayedList()`, `backToComparison()` store actions already exist and are exactly what the header's view-switch icons should call
- `dirtyGameIds.length` (syncCount) and `sessionId` (syncDisabled) — already computed in ComparisonView for the Sync menu item; needed wherever the header lives

### Established Patterns
- Every view is a flat top-level component rendered by `App.tsx`'s `view === '...'` conditionals (App.tsx:29-36) — no shared layout wrapper exists today. The new header will likely need to become a wrapper or be rendered per-view from a shared component.
- Tailwind utility classes are used directly, no CSS modules/styled-components; button style pattern is consistent (`px-N py-N border border-gray-200 rounded text-sm ... outline-2 outline-offset-2 outline-blue-600`).

### Integration Points
- `App.tsx` — where the four views are switched; likely where a shared header wrapper gets introduced
- `store.ts` `view` state and the transitions listed in D-10 — must be updated together with the header's default-view expectations
