    Structure:
    - `import express from 'express'`, `import cors from 'cors'`, `import https from 'node:https'`. Apply `app.use(cors({ origin: process.env.ALLOWED_ORIGIN ?? '*' }))` and JSON body parsing (`app.use(express.json())`) plus a raw/text fallback so non-JSON bodies still forward.
    - Module-scoped mutable cache: `let proxySession = null` (mirrors vite.config.ts line 22 — full cookie string from last successful login; wiped on process restart/cold start, which is expected per 05-RESEARCH.md Pitfall 2 — do NOT add persistent storage).
    - Route `GET /healthz` → `res.sendStatus(200)` (needed by render.yaml `healthCheckPath` and SC-1 live verification).
    - Catch-all handler (`app.use(async (req, res) => { ... })`) that:
      1. Computes `isLogin = req.path.startsWith('/login')`.
      2. Reads `req.headers['x-bgg-session']`, passes it through `sanitizeSessionToken()`.
      3. Computes `cookieHeader = isLogin ? undefined : (proxySession ?? (token ? \`SessionID=${token}\` : undefined))`. (Fallback note: after a cold start proxySession is null and this degrades to a SessionID-only cookie; the SPA's existing 401 → reAuthAndResume flow recovers — document, do not "fix".)
      4. Makes an outbound `https.request({ hostname: 'boardgamegeek.com', path: req.originalUrl, method: req.method, headers: {...} })` — `hostname` HARDCODED (SSRF mitigation, never client-derived). Forward `content-type` (default `application/json`) and set `Cookie: cookieHeader` only when defined. Write the request body when present (`JSON.stringify` object bodies, pass strings through), then `.end()`. On `upstream.on('error')` respond `res.status(502).json({ error: err.message })`.
      5. In the upstream response callback: if `isLogin`, read `upstreamRes.headers['set-cookie']` (native array from the https module — NEVER use fetch().get('set-cookie'), which comma-merges cookies per Pitfall 1), compute `sessionId = extractSessionId(cookies)`, and if truthy set `proxySession = buildSessionCookie(cookies)`. Respond `res.json({ sessionId })` — never relay Set-Cookie to the browser (AUTH-03 / D-08). Always return JSON even on BGG 204/400 (a 204 body is dropped by browser fetch), mirroring vite.config.ts lines 62-71.
      6. If not login: relay status code unmodified (MUST pass a 202 through untouched per CLAUDE.md), copy only the allowlisted headers `['content-type', 'content-length', 'cache-control']` (never blanket-relay — would leak Set-Cookie), and pipe the upstream body to `res`.
    - Listen on `process.env.PORT || 10000` — Render injects `PORT` and the service MUST bind to it, or the deploy health check fails. Log the listening port.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SPA (browser) → Render proxy | Untrusted client input crosses here: X-BGG-Session header, request path, body |
| Render proxy → boardgamegeek.com | Server-to-server; upstream host must never be client-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | `server.js` X-BGG-Session → outbound Cookie header | mitigate | `sanitizeSessionToken()` rejects anything outside `^[A-Za-z0-9_-]+$` before the value is interpolated into the Cookie header (unit-tested in Task 1) — prevents CRLF/header injection |
| T-05-02 | Elevation of Privilege | `server.js` upstream `https.request` host | mitigate | `hostname: 'boardgamegeek.com'` hardcoded; never derived from req path/header/query — prevents SSRF |
| T-05-04 | Information Disclosure | `server.js` /login response path | mitigate | Set-Cookie from BGG is never relayed to the browser; only synthesized `{sessionId}` JSON returned (AUTH-03 / D-08). Non-login paths copy an explicit header allowlist only |
| T-05-SC | Tampering | npm installs (`express`, `cors`) | mitigate | Both audited OK/Approved in 05-RESEARCH.md Package Legitimacy Audit (official expressjs org, no postinstall scripts); no `[ASSUMED]`/`[SUS]` packages → no blocking legitimacy checkpoint required |
</threat_model>
