## Unsatisfied Requirements

### PERSIST-02: Return-Visit Auto-Resume — BLOCKER ⛔

**Phase:** 4 (Display Polish)
**Symptom:** Every login triggers a full BGG collection re-fetch and re-seed, discarding in-progress session state.

**Root cause:** `login()` in [store.ts:393-408](src/store/store.ts#L393-L408) always calls `fetchCollection(username)` after `bggLogin()` succeeds. The PERSIST-02 guard documented in 04-02-SUMMARY.md ("if `rankingsUsername === username AND ratings non-empty AND games non-empty`, call `continueSession()` instead of `fetchCollection()`") was described as implemented but is absent from the code.

**Impact:**
- A returning user who logs in with the same username they used last time gets a full re-fetch instead of continuing where they left off
- `dirtyGameIds` is recomputed from a fresh seed — their unsynced comparison work is discarded
- `continueSession()` exists and is correctly implemented (store.ts:257-265) but is never called from `login()`

**Fix:**
```ts
// After: set({ sessionId: result.sessionId, sessionUsername: username })
const { rankingsUsername, ratings, games } = get()
if (
  rankingsUsername === username &&
  Object.keys(ratings).length > 0 &&
  Object.keys(games).length > 0
) {
  get().continueSession()
  return
}
set({ loadingMessage: 'Fetching your games…' })
await get().fetchCollection(username)
```

**Tests to update:** `store.test.ts` describe block `'login() auto-resume (D-07)'` — Test 1 ("mockBggFetch should NOT have been called for same user with rankings") will turn RED until the fix is applied, then GREEN.
